红米 K30 至尊纪念版 · A16/A17 内核操作清单

cezanne / M2006J10C / MT6889 天玑1000+ · 内核 4.14.186 · VNDK 31 · A-only · 无 EROFS
13/13 patch 已验证可 apply sk_msg 0 → 118 btf_vmlinux 0 → 31 刷内核不需要底包 刷内核不需要 Recovery
这份清单要干什么：编译一个带 BPF backport + EROFS + uname 伪装 的 4.14.186 内核，让 cezanne 能跑 Android 16/17 移植包。
当前状态：手机跑着 A16 crDroid 12.12（零崩溃）。这一步是为将来换 A17 移植包铺路，不是立刻要刷的东西。
三条铁律：① kernel-release 必须等于 4.14.186-perf-00252-g2f26b5917fd6，不等就别刷；② 本机无 EROFS，系统分区仍需 ext4（内核支持 ≠ 分区可用）；③ MT6889 变砖极难救回，刷之前先备份 boot。

1准备（不用下底包）

# 在仓库目录下
cd kernel-bpf
git init
git add .
git commit -m "feat: cezanne BPF kernel build for Android 16/17"
git remote add origin https://github.com/你的用户名/kernel-bpf.git
git push -u origin main
不需要下载的东西：底包 V12.5.11.0（4.76GB）、Recovery、任何 ROM。刷内核只动 boot 分区，不碰 vendor/data/super。

2触发 Actions 编译

  1. GitHub 打开你的 kernel-bpf 仓库 → Actions 标签
  2. 选 Build cezanne BPF kernel (for Android 16/17)
  3. 点右侧 Run workflow
  4. 参数按下面填
参数填为什么
enable_erofs✔ 勾A15+ 分区是 erofs，没驱动直接卡开机
enable_bpf✔ 勾核心。回合 5.10 的 sk_msg / BTF / arraymap 修复
enable_uname✔ 勾放行 BPF 加载器对内核版本的检查
enable_ksu✘ 不勾第一次先验证能不能开机，变量越少越好
localversion-perf-00252-g2f26b5917fd6不要改，改了原厂 vendor 的 10 个 .ko 全加载失败

跑完（30~60 分钟）在运行页底部 Artifacts 下载 cezanne-kernel-bpf。

3拿到包后 · 三项自检

这一关过不了就不要刷。
# 一键检查
cat kernel-release.txt
grep -E "CONFIG_(EROFS_FS|DEBUG_INFO_BTF|BPF_SYSCALL|CGROUP_FREEZER)=y" config.txt
cat BUILD-INFO.txt

三项全过 → 进下一步。有任何一项不过 → 把 build.log 贴给我，我帮你看。

4备份（刷之前必做）

MT6889 在 Mi Flash / SP Flash Tool 下兼容性很差，变砖后极难救回。这一步不能省。
# 1. 进 fastboot
adb reboot bootloader

# 2. 备份当前 boot（这是你的救命稻草）
fastboot fetch boot.img boot_backup.img
# 或
fastboot flash boot boot_backup.img   # 校验写入成功

# 3. 顺便看看当前内核版本
fastboot getvar product
fastboot getvar unlocked
fastboot getvar anti

5刷入（两种方式，选一种）

方式 A · fastboot 直刷（推荐，不用 Recovery）

AnyKernel3 包本质是带刷机脚本的 zip，直接刷 boot 分区即可。

# 解压 anykernel3.zip，取出 Image.gz
# 然后直接刷（需要自己组 boot.img）
fastboot flash boot boot_new.img

# 或者用 AnyKernel3 包 + 自定义 recovery
fastboot flash recovery recovery.img
fastboot reboot recovery
# 进 recovery → Install → 选 *-gz-anykernel3.zip

方式 B · Recovery 卡刷（更稳）

如果你手上有能用的 Recovery（下列任一），直接在里面 Install 刷 *-gz-anykernel3.zip：

Recovery大小链接
TWRP 3.4.2B (LR.Team)35.68 MBmifirm.net/downloadtwrp/189
TWRP (通用)42.17 MBmifirm.net/downloadtwrp/166
PitchBlack Recovery42.91 MBmifirm.net/downloadtwrp/177
后续刷 A17 移植包时，需要一个能解密 data 的 Recovery（否则 keystore2 加载失败，A17 直接开不了机）。酷安上的 解密版 OrangeFox 明确支持「MIUI14 Android 13 解密 + Android12 MIUI13/14 官方ROM和类原生解密」。

6验证

7回滚（任何一步不对就用这个）

# 进 fastboot
adb reboot bootloader
# 刷回原厂 boot
fastboot flash boot boot_backup.img
# 重启
fastboot reboot

30 秒内回到原状态。这就是为什么第 4 步的备份不能省。

8后续：换 A17 移植包（等内核跑稳再说）

阶段要做什么
① 底包下 MIUI V12.5.11.0.RJNCNXM（约 4.76GB）—— 既是刷 ROM 必需，也是最终救砖包
② Recovery解密版 OrangeFox（能解 data，否则 keystore2 失败）
③ ROM 包HyperOS4 A17（OS4.0.0.10，源小米 17T Pro）—— 酷安积分墙后，可能拿不到
③′ 备选ColorOS 14（Mystic Coloros-ossi-14-…，SourceForge 免费公开）。A14 门槛正好 4.14 达标，不需要新内核，只需换 com.android.tethering.apex
④ 刷底包 → 四清 + 格式化 data → 刷 ROM → 刷内核
关于 QPR 版本：社区结论是「5.4 的 bpf 也只能开 qpr0」→ A16/A17 只能 QPR0，QPR2 不行。这也是为什么 Ty_1224 用的是 OS4.0.0.10（QPR0 系）。
ColorOS 14 路线反而更省：不需要新内核（4.14 刚好达标），Mystic 的包在 SourceForge 完全免费公开。代价是 OPPO 私有服务/相机/GPU 调校对不上 MTK，成功率低于 HyperOS（同血脉优势）。

9已知坑（都是这次调研踩出来的）

坑实情
酷安「查看链接」不是作者收费，是酷安积分/等级墙。未登录连回复都读不到 → A17 移植包可能弄不到
FiimeROM 的 cezanne 包SEO 拼凑，FindROM/102345.html 实测 404，另两个编号是编造连号
ROM基地「澎湃OS4 安卓16 大小1」引流假条目
cezanne-aosp_a14 内核包是 4.14 内核，不解锁 A15/A16，别误读
Windows 编译内核内核树有 aux.c/aux.h 大小写冲突 → Windows 上无法全树 checkout，必须用 Actions（Linux）
mt6768 的分支不是 main，是 skyron
FOD 屏下指纹GSI 架构缺口（vendor HAL 回调为 null），换任何内核都修不好
